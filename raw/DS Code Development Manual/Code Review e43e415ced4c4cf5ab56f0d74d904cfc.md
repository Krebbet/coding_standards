# Code Review

The code review is an interactive process between developers and code reviewers that allows moving SFL Scientific's overall code quality towards a higher optimal standard. This in turn leads to better and cleaner code being delivered to clients.

# **Code Review Assignment Process**

The tech lead for each project is responsible for either completing or assigning code review.

In some cases, a code reviewer will be assigned by the PM. Each PR will require approval from the reviewer. The developer is responsible for assigning the correct reviewer to their PR.

# Code Reviews Speed Expectations

**As fast as possible.** If you are not in the middle of a focused task, you should do a code review shortly after it comes in. Ideally, if the PR is received before noon, reviews should be complete by the end of that day. Otherwise, it should be the first thing for the next morning. One business day is the maximum time it should take to respond to a code review request.

This rule should also apply when dealing with time zone differences. If the review cannot be finished by the time the author leaves the office, try to make sure your review is done before they get back to the office the next day.

To manage expectations and project time, ***all code reviews should be done within 24hrs of a PR***. Please note that if the assigned reviewer has urgent deadlines that prevent timely completion of a code review, he/she should inform the PM asap so that the other reviewer can take over.

Developers are expected to own the responsibility of resolving all comments in a comprehensive and expeditious fashion. Generally, a PR process (opening, code review, revision, resubmission, approval, and merge) should take less than 36 hours. Unique situations should be discussed with the PM.

**Key Code Review Timing Takeaways**

- PRs should be reviewed as soon as possible — at most within 24 hours.
- The entire PR lifecycle from creation to merge should generally take less than 36 hours.
- All exceptions to these timings should consider overall impact to a project's timelines and be discussed with PMs.
