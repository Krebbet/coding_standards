# Unit Tests

[testing-library/react-testing-library](https://github.com/testing-library/react-testing-library#basic-example)

The example provides sample code on how to setup and run unit tests in React.js. However, there are React-specific overhead that is required, which may distract from the testing aspect. This section includes pseudocode for the logic and design of unit tests which are transferable to any language. 

## The Application's Design

Take the Simple application wireframe shown here:

![](Unit%20Tests/126240D3-36CA-436E-AFDC-01ED1DB11D4F.jpeg)

The Simple app has a text input field (1), a GO button (2) to commit the input, and a table of Previous Entries that will display past and recently committed entries (3). This is a design that has been developed and agreed upon for execution. The design can be made more clear for each of the elements. 

Text Input Field (1) should:

- Accept any ASCII string
- Make sure all inputs are interpreted as a string

GO Button (2) should:

- Take the string value of (1)
- Create a new entry with value
- Save the entry to the server

And the Table of Previous Entries (3) should:

- Load previous entries
- Limit the maximum number of entries

This is a decent number of items and limitations to begin work; more will be added throughout the course of development, which may show up in testing.

## The Tests for Text Input Box

The text input (1) of Simple app will have a set of expected inputs and behaviors. The two limitations that have been identified are input limitations and checks. The function `getBoxText()` will probably be used to obtain the text input value, perform the checks and formatting, and return a string that can be stored into the table.

```jsx
/*
 * Tests for Text Input Box (1).
 */

test('Only ASCII works', () => {
	// Input and retrieve the text.
	var input = "some ascii 123 )(*&^";
	injectIntoTextBox(input=input, elemId="TextInputBox_1")
	var output = getBoxText(elemId="TextInputBox_1")
	// The input and output should be the same
	expect(output).toBe(input) // expect() is a function from Jest

	// Repeat for non-ASCII
	input = "♩ ♪ ♫ ♬ ♭ ♮ ♯";
	injectIntoTextBox(input=input, elemId="TextInputBox_1")
	output = getBoxText(elemId="TextInputBox_1")
	// The output should be Null
	expect(output).toBeNull() 

	// Repeat for empty input
	input = "";
	injectIntoTextBox(input=input, elemId="TextInputBox_1")
	output = getBoxText(elemId="TextInputBox_1")
	// The output should be an empty string
	expect(output).toBe("")
});

test('Everything should be a string', () => {
	// Check non-string input w/ expected string output
	var input = 123
	var strInput = "123"
	injectIntoTextBox(input=input, elemId="TextInputBox_1")
	output = getBoxText(elemId="TextInputBox_1")
	// The output should be equal to the string
	expect(output).toBe(strInput)
});
```

The tests above present two functions that may (or may not) be key in developing the Simple app. Neither function is a hard requirement. Writing them here is additional work, but the goal is to reduce future work. 

`injectIntoTextBox()` is written in here as a function, but it may be substituted with a scraping framework such as Puppeteer or Selenium. These frameworks provide functions that can identify and simulate inputs. In most cases, this is sufficient.

`getBoxText()` may or may not include the checks needed to check inputs. It also may or may not be included further down stream from Input Text Box (1). If it is not included within the tests for this component, it would have to be included in the next component, GO Button (2). Pay tech debt off, today!

## Changes and Enhancements Requested

If changes or enhancements are requested, tests will have to be re-written or updated to accommodate them. The quantity and quality of tests required should be included in gauging the overall difficulty of implementation. Imagine a client comes back and wants a new function to be included within Input Text Box(1) such that:

- Inputs must start with a letter `[a-zA-Z]`, displaying an error otherwise
- If the input string has already been added to the table, recommend it

Reviewing the previous tests for Input Text Box (1) from the first version of Simple app, the non-ASCII test and empty string tests no longer work; their outputs and `expect()`'s must be changed to an error message instead of None or empty strings. To accommodate changes in what can cause the Error Message (2.1), addition input strings would be required. This can be considered a change request.

To handle the far more complex Recommendation / Autofill (2.2), an entire new suite of tests must be written. This can be considered an enhancement.
