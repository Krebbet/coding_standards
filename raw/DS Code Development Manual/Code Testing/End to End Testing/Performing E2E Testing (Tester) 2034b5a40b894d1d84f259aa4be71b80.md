# Performing E2E Testing (Tester)

## Tester Responsibilities

The tester has one main responsibility, to determine if an end-user will reasonably be able to install and utilize each feature of the application on their own. In order to more accurately represent an end-user, employees who are least involved in the project are preferentially selected. 

As a tester you should try to best represent the end user's level of technical proficiency. If this hasn't been specifically laid out, assume the end user will have little to none. During testing, think naive user thoughts: 

> I'll turn my brain down to 0.
> 

## Opening GitHub Issues

For each problem identified, (whether it's a bug, confusing piece of documentation, or otherwise) the tester should open an issue on the projects GitHub. Ensure that you include sufficient information for the developer to identify the issue. In particular for bugs include as many specifics on how to replicate the issue. If there's a piece of documentation that is unclear, be sure to specify the document and the piece's location within it.
