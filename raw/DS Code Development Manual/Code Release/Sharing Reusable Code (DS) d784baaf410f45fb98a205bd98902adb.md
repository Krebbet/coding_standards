SFL Scientific prides itself on proofs-of-concept and project-tuned development, so it may not sound intuitive to start building a repository of reusable code. However, sharing good functions, figures, and training paradigms can jump-start new projects and reduces time spent figuring out the same problem over and over again. 

In addition to the benefits to your project work, interacting with this repo counts as a **Firm Contribution**. See the [](https://www.notion.so/a02d6c218e1640f9b32edfb6aced5c93?pvs=21) for level-based guidelines for use.

## Expectations for Use

The following are role-based guidelines for how Delivery Team members can use and contribute to this initiative. Meeting or exceeding the guidelines for your role is considered a Firm Contribution. Here, IC stands for “Independent Contributor.”

| Project Managers and Project Coordinators | Encourage efficient repository utilization in projects 

Encourage code revisions or submissions at project end 

Mentors ICs through the process of repository usage |
| --- | --- |
| Data Scientist | Uses and leverages the library functions intelligently in their projects |
| Senior Data Scientist | Regularly contributes to and/or manages the library |
| Technical Lead+ | Strategically identifies trends, drives organization and clean up, and reviews to maintain high quality standard of library 

Mentors ICs through the process of repository usage |

Exceptional contributors and maintainers will be considered for awards through internal recognition programs.
