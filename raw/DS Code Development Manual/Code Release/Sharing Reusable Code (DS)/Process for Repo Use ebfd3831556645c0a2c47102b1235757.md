# Process for Repo Use

[Link to repository](https://github.com/Deloitte/SFL-Code-Reuse)

The initial repository is **not** intended for use as a module or package. Function requirement lists will live in the relevant folder. A developer is expected to copy and paste functions of interest and their associated requirements needed into their own repository. As this project matures, commonly used function groups may spin off into their own contained packages.

1. **When the first piece of data is received**, a developer will be assigned to check the repo
    
    > Assign one developer to check the repository and find 3-5 functions the team may be able to leverage. If no functions are chosen, explain why.
    > 
    
    Feedback on repo usability and usefulness should be forwarded to the `code-reusers` team.
    
2. Developers are expected and encouraged to modify the functions to their use-case in their repository.
3. Project-agnostic modifications (bugfixes, new features, more concise documentation, etc) may be submitted to the `SFL-Code-Reuse` repository for future developers.
