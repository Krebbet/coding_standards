# Quickstart

# Quick Reference

1. Standardize to the [SFL template](https://github.com/Deloitte/SFL-Template)(s). 
2. Follow our Naming Conventions for [branches](../Version%20Control%20(Git%20&%20GitHub)/Branch%20Standards%205c2d132560384b00ae5d7377076af9c7.md) and [notebooks](../Writing%20Code/Jupyter%20Notebook%20Guidelines%20d8d4eab8446a4aa586026326d9cf0689.md).
3. Ensure that code follows the [Code Guidelines](../Writing%20Code/Code%20Standards%20bb20e0f77b0f4d52b8d416a19ef1699b.md).
4. [Issues](../Version%20Control%20(Git%20&%20GitHub)/Issues%20Standards%2090450972bfa8482bafbe16a424105b99.md) can initially be kept as TODOs, but should be migrated to Github’s Issue Tracker upon a push to the main branch.
5. Keep [commits](../Version%20Control%20(Git%20&%20GitHub)/Commit%20Standards%20a5eea8eb3ef24c0789778eff29d890eb.md) function-based and documented.
6. Use [Pull Requests](../Version%20Control%20(Git%20&%20GitHub)/Pull%20Request%20Standards%204c2301249b194eb7970eab97105d5db6.md)  to request a merge to master, which will also trigger a code review. 
7. All [code released to clients](../Code%20Release/Releasing%20Code%20to%20Clients%20bb332cd246b24ae4bf6e48c3ee1640f0.md) must undergo testing and be handed off via a signed release.
