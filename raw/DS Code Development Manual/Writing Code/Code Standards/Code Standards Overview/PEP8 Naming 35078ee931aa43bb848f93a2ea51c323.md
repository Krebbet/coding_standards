# PEP8 Naming

Level: Class, Documentation, Function, Library
Constraint: Hard
Last Edit: October 26, 2023 2:24 PM
Project Types: GA, MVP, POC

## Follow PEP8 Naming

All names of variables, functions, classes and globals should follow PEP8 Guidelines. 

Filenames should be clear and ideally full words that are underscore separated. 

Variables and functions should be all lower case with underscore separation, ideally full words are preferred unless the combination is very long. Variables also may hint at the type of the variable e.g. “data_df” or “conversion_dict” etc to allow for ease of understanding.

Classes should be camelcase. Each script should typically only have one class and its associated subclasses. 

Global variables should be all uppercase with underscore separation. Global variables should also typically be specified in a config or near the top of the script. 

*Exceptions to these rules can be commonly referenced names e.g. “X” for feature input into a model is sometimes used.*

**Bad:**

```python
fooBar = 7
fooBAR = 7
foo_BAR = 7

def processDF():
	 ...

def ProcessDF():
	...

def Process_DF():
	...
```

**Good:**

```python
foo_bar = 7 # if local
FOO_BAR = 7 # if global

# function definitions separated by _
def process_df():
	...

# camel case for classes
class TriangeShape:
	...
```
