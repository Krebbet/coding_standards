# Design with Clear Contracts (Typed Inputs/Outputs)

### **What this means**

Minimize business logic that directly manipulates “raw” structures like `dict`, `list`, `tuple`, `set`, `bytes`, or untyped JSON payloads. Treat those structures as **transport / persistence formats**—not your application’s internal language.

### **Why it matters (the failure modes)**

- **Hidden schemas**: A “shape” (required keys, allowed values, invariants) exists, but it’s enforced nowhere, so it rots silently.
- **Stringly-typed logic**: Key names and magic indices become implicit APIs that are hard to refactor safely.
- **Validation scattered everywhere**: Each call site re-checks nullability, defaults, and conversions inconsistently.
- **Error handling gets vague**: Failures become `KeyError`/`IndexError`/`TypeError` far from the boundary, with poor diagnostics.
- **Tests become brittle**: You unit-test large blobs of dicts instead of stable domain behaviors.

## Principle: “Translate at the edges, speak domain inside”

**Rule of thumb:** Convert raw inputs **once** at a boundary into a well-defined type, then keep the inside of the system working with **domain objects**.

### Common “edges” (where raw structures are fine)

- HTTP handlers / request parsing
- Queue consumers / producers
- File I/O (CSV/JSON/YAML)
- DB rows / ORM models
- Third‑party SDK responses

### “Inside” (where raw structures should be rare)

- Domain services (pricing, eligibility, scheduling, compliance rules)
- Core workflows / use cases
- Cross-module interfaces

## Recommended patterns (pick what fits your stack)

### 1) Domain models + value objects

Create explicit types that represent your concepts and invariants (e.g., `Money`, `EmailAddress`, `CustomerId`, `Invoice`). Keep validation and normalization *inside* these types.

**Benefits:** invariants are centralized; call sites get simpler; refactors are safer.

### 2) DTOs / Schemas at boundaries

Use a schema layer to validate/parse raw payloads into typed objects (e.g., dataclasses or a validation library). The key is: **raw dict in → validated object out**.

**Benefits:** consistent defaults, better errors, and fewer downstream checks.

### 3) Adapters (anti-corruption layer)

For third-party APIs, create an adapter that maps vendor responses into your internal types. Never let vendor-shaped dicts leak into domain logic.

**Benefits:** isolates vendor churn; keeps domain language clean.

### 4) Repository pattern for persistence

Translate DB rows/ORM entities into domain models in repositories, not in business logic.

**Benefits:** business logic stops caring about storage representation.

### 5) Typed interfaces for collections

If you must pass “collections of things,” pass `Sequence[Order]` rather than `list[dict]`; pass `Mapping[CustomerId, Customer]` rather than `dict[str, dict]`.

**Benefits:** makes contracts explicit; improves readability and tooling.

## Anti-patterns to call out explicitly

- Business rules implemented as `payload["x"]["y"][0]` chains
- Functions that accept/return “bag of fields” dicts (“just add one more key…”)
- Cross-module APIs that expose raw JSON/dicts as their contract
- Domain logic that “knows” API key names, DB column names, or message schemas
- Mutating shared dicts across steps (hard to reason about state and ownership)

## Code Example of “Hidden Schemas”

```python
# Code Generated by Sidekick is for learning and experimentation purposes only.
def apply_discount(order: dict, user: dict) -> dict:
    # ❌ Anti-pattern: business logic directly on nested dicts/lists,
    # magic keys, scattered defaults, implicit schema, and mutation.

    # Implicit schema assumptions everywhere:
    tier = user.get("tier") or "standard"
    cart = order.get("cart") or {}
    items = cart.get("items") or []

    # Magic numbers and key names baked into logic:
    subtotal = 0.0
    for item in items:
        subtotal += float(item["unit_price"]) * int(item.get("qty", 1))  # KeyError/ValueError risk

    # Tier rules encoded as stringly-typed conditionals:
    if tier == "gold":
        discount_rate = 0.15
    elif tier == "silver":
        discount_rate = 0.10
    else:
        discount_rate = 0.0

    # More implicit schema: coupon may exist, or not, in several shapes:
    coupon = order.get("coupon")
    if coupon and coupon.get("type") == "percent":
        discount_rate = max(discount_rate, float(coupon.get("value", 0)) / 100.0)

    # Mutating shared input dicts (side effects leak across the app):
    order["pricing"] = order.get("pricing") or {}
    order["pricing"]["subtotal"] = round(subtotal, 2)
    order["pricing"]["discount_rate"] = discount_rate
    order["pricing"]["total"] = round(subtotal * (1 - discount_rate), 2)

    return order

# Somewhere else: callers pass whatever shape they have on hand:
order_payload = {
    "cart": {"items": [{"unit_price": "19.99", "qty": "2"}]},
    "coupon": {"type": "percent", "value": "5"},
}
user_payload = {"tier": "silver"}

print(apply_discount(order_payload, user_payload))
```

## Code Example of Design with Clear Contracts

```python
from __future__ import annotations

from dataclasses import dataclass
from decimal import Decimal, ROUND_HALF_UP
from enum import Enum
from typing import Any, Mapping, Sequence

# ----- Domain types (your application's internal language) -----

class Tier(str, Enum):
    STANDARD = "standard"
    SILVER = "silver"
    GOLD = "gold"

@dataclass(frozen=True)
class Money:
    amount: Decimal

    def __post_init__(self) -> None:
        if self.amount.is_nan():
            raise ValueError("Money amount cannot be NaN")

    def quantize_2dp(self) -> Money:
        return Money(self.amount.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))

    def __mul__(self, other: Decimal) -> Money:
        return Money(self.amount * other)

    def __add__(self, other: Money) -> Money:
        return Money(self.amount + other.amount)

@dataclass(frozen=True)
class LineItem:
    unit_price: Money
    quantity: int

    def __post_init__(self) -> None:
        if self.quantity <= 0:
            raise ValueError("quantity must be > 0")

    def total(self) -> Money:
        return (self.unit_price * Decimal(self.quantity)).quantize_2dp()

@dataclass(frozen=True)
class CouponPercent:
    percent: Decimal  # e.g., 5 == 5%

    def __post_init__(self) -> None:
        if self.percent < 0 or self.percent > 100:
            raise ValueError("coupon percent must be 0..100")

    @property
    def rate(self) -> Decimal:
        return (self.percent / Decimal("100"))

@dataclass(frozen=True)
class Order:
    items: Sequence[LineItem]
    coupon: CouponPercent | None = None

@dataclass(frozen=True)
class User:
    tier: Tier

@dataclass(frozen=True)
class Pricing:
    subtotal: Money
    discount_rate: Decimal
    total: Money

# ----- Pure domain logic (no dicts, no mutation, clear contracts) -----

def tier_discount_rate(tier: Tier) -> Decimal:
    return {
        Tier.GOLD: Decimal("0.15"),
        Tier.SILVER: Decimal("0.10"),
        Tier.STANDARD: Decimal("0.00"),
    }[tier]

def price_order(order: Order, user: User) -> Pricing:
    subtotal = Money(Decimal("0"))
    for item in order.items:
        subtotal = subtotal + item.total()

    rate = tier_discount_rate(user.tier)
    if order.coupon is not None:
        rate = max(rate, order.coupon.rate)

    total = (subtotal * (Decimal("1") - rate)).quantize_2dp()
    return Pricing(subtotal=subtotal.quantize_2dp(), discount_rate=rate, total=total)

# ----- Edge translation (raw dict in; validated domain objects out) -----

def parse_order(payload: Mapping[str, Any]) -> Order:
    try:
        raw_items = payload["cart"]["items"]
    except Exception as e:
        raise ValueError("Invalid order payload: missing cart.items") from e

    items: list[LineItem] = []
    for i, raw in enumerate(raw_items):
        try:
            unit_price = Money(Decimal(str(raw["unit_price"])))
            quantity = int(raw.get("qty", 1))
            items.append(LineItem(unit_price=unit_price, quantity=quantity))
        except Exception as e:
            raise ValueError(f"Invalid line item at index {i}") from e

    coupon = None
    raw_coupon = payload.get("coupon")
    if isinstance(raw_coupon, Mapping) and raw_coupon.get("type") == "percent":
        coupon = CouponPercent(percent=Decimal(str(raw_coupon.get("value", "0"))))

    return Order(items=items, coupon=coupon)

def parse_user(payload: Mapping[str, Any]) -> User:
    tier_str = str(payload.get("tier", "standard")).lower()
    try:
        tier = Tier(tier_str)
    except ValueError as e:
        raise ValueError(f"Invalid tier: {tier_str}") from e
    return User(tier=tier)

# ----- Example usage -----

order_payload = {
    "cart": {"items": [{"unit_price": "19.99", "qty": "2"}]},
    "coupon": {"type": "percent", "value": "5"},
}
user_payload = {"tier": "silver"}

order = parse_order(order_payload)   # boundary: validate/convert once
user = parse_user(user_payload)      # boundary: validate/convert once
pricing = price_order(order, user)   # inside: domain types only

print(pricing)
```
