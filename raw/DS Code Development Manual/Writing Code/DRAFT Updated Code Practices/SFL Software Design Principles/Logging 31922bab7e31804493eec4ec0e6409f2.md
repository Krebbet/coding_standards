# Logging

## Logging (Python) — design principles for production-grade code

### **Treat logs as a product interface**

- Write logs for *operators* (on-call, SREs, support) and *future you*: clear event name, what happened, where, and what to do next.
- Prefer *high-signal, low-volume* logs; avoid “I got here” noise.

### **Use the standard library logging API everywhere**

- In application and libraries, log via named loggers (module/package-level), not prints.
- Library code should **emit** logs; the **application entrypoint** should **configure** handlers/format/levels.

### **Be intentional with levels**

- `DEBUG`: diagnostic detail for developers (often off in prod).
- `INFO`: meaningful state changes / business events (start/stop, completed steps).
- `WARNING`: unexpected but recoverable conditions (fallbacks, retries).
- `ERROR`: operation failed; user impact likely.
- `CRITICAL`: service integrity compromised; immediate action.

### **Prefer structured, contextual logs**

- Make it easy to search/aggregate: include stable fields like `event`, `component`, `request_id/correlation_id`, `user_or_tenant_id` (if allowed), `duration_ms`, `status`, `error_type`.
- Add context consistently (e.g., request IDs) so one trace can be followed across modules/services.

### **Log exceptions correctly**

- Log exceptions *once* at the right boundary (where you decide to handle/return an error), and include stack traces.
- Avoid swallowing exceptions with a vague message; include the failing operation and key parameters (sanitized).

### **Don’t leak secrets or PII**

- Establish “never log” rules (tokens, passwords, raw personal data).
- Prefer allow-lists of safe fields and redaction patterns; treat logs as potentially widely accessible.

### **Design for deployment realities**

- Consider where logs go (stdout for containers, files for VMs, central collectors) and size/retention.
- Use rotation/retention (or platform logging) to avoid disk issues; consider rate-limiting/sampling for hot paths.

### **Make logs testable and maintainable**

- Use consistent event naming and message style; document common events.
- In unit tests, assert key log events/fields (not exact strings) to avoid brittle tests.

### **Common anti-patterns to call out**

- `print()` in production paths; configuring logging inside libraries; logging in tight loops without sampling; logging large payloads; duplicate exception logs at multiple layers; using dynamic log messages without stable fields.

## Code Example of Poor Logging in Python

```python
"""
Intentionally poor logging example — do NOT copy into production.
Demonstrates common anti-patterns:
- uses print instead of logging
- configures global logging in library-like code
- logs sensitive data
- swallows exceptions
- logs without context (no request_id, no event name)
- logs at wrong levels and duplicates errors
"""

import logging
import random
import time

# Anti-pattern: configuring logging in a module that might be imported as a library.
logging.basicConfig(level=logging.DEBUG)

def charge_card(user_email: str, card_number: str, amount: float) -> str:
    # Anti-pattern: mixing print and logging; no structured context.
    print("Starting payment...")

    # Anti-pattern: logging secrets/PII (card number, email).
    logging.info("Charging %s with card=%s for amount=%s", user_email, card_number, amount)

    try:
        # Simulate flaky dependency
        if random.random() < 0.5:
            raise TimeoutError("gateway timeout")

        # Anti-pattern: debug spam with no value.
        for i in range(5):
            logging.debug("loop i=%s", i)

        time.sleep(0.1)

        # Anti-pattern: meaningless success message.
        logging.info("Payment done!")
        return "OK"

    except Exception as e:
        # Anti-pattern: logs exception twice; no stack trace; no action guidance.
        logging.error("Payment failed: %s", e)
        print("ERROR occurred")

        # Anti-pattern: swallowing exception and returning ambiguous status.
        return "FAILED"

if __name__ == "__main__":
    # Anti-pattern: hard-coded sensitive test data.
    result = charge_card("alice@example.com", "4111111111111111", 19.99)
    print("Result:", result)
```

## Code Example of Clean Logging

```python
"""
Clean logging example (stdlib only):
- Library code uses a named logger and never calls basicConfig()
- Application entrypoint configures logging once
- Consistent, searchable fields via `extra` (works with any formatter)
- No secrets/PII in logs (e.g., no card numbers)
- Exceptions logged once, with stack trace, at the right boundary
- Measures duration and includes correlation/request id
"""

from __future__ import annotations

import json
import logging
import time
import uuid
from dataclasses import dataclass
from typing import Optional

# ----------------------------
# "Library" / business logic
# ----------------------------

logger = logging.getLogger("payments")

@dataclass(frozen=True)
class ChargeRequest:
    request_id: str
    user_id: str
    payment_method_id: str  # token/ID, not raw PAN
    amount_usd: float

class PaymentGatewayError(RuntimeError):
    pass

def _call_gateway(payment_method_id: str, amount_usd: float) -> str:
    # Simulate a dependency call
    if amount_usd <= 0:
        raise ValueError("amount_usd must be positive")
    # Pretend we got a transaction id back
    return "txn_" + uuid.uuid4().hex[:12]

def charge(req: ChargeRequest) -> str:
    start = time.perf_counter()

    # High-signal INFO log: state change / important event.
    logger.info(
        "charge.started",
        extra={
            "event": "charge.started",
            "request_id": req.request_id,
            "user_id": req.user_id,
            "payment_method_id": req.payment_method_id,
            "amount_usd": req.amount_usd,
            "component": "payments",
        },
    )

    txn_id = _call_gateway(req.payment_method_id, req.amount_usd)

    duration_ms = int((time.perf_counter() - start) * 1000)
    logger.info(
        "charge.succeeded",
        extra={
            "event": "charge.succeeded",
            "request_id": req.request_id,
            "user_id": req.user_id,
            "payment_method_id": req.payment_method_id,
            "amount_usd": req.amount_usd,
            "txn_id": txn_id,
            "duration_ms": duration_ms,
            "component": "payments",
        },
    )
    return txn_id

# ----------------------------
# Application entrypoint
# ----------------------------

class JsonFormatter(logging.Formatter):
    """Tiny JSON formatter; keeps message + selected record extras."""
    def format(self, record: logging.LogRecord) -> str:
        payload = {
            "ts": self.formatTime(record, self.datefmt),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
        }
        # Include common structured fields when present
        for key in (
            "event",
            "component",
            "request_id",
            "user_id",
            "payment_method_id",
            "amount_usd",
            "txn_id",
            "duration_ms",
        ):
            if hasattr(record, key):
                payload[key] = getattr(record, key)

        if record.exc_info:
            payload["exc_info"] = self.formatException(record.exc_info)

        return json.dumps(payload, separators=(",", ":"), ensure_ascii=False)

def configure_logging(level: int = logging.INFO) -> None:
    handler = logging.StreamHandler()
    handler.setFormatter(JsonFormatter(datefmt="%Y-%m-%dT%H:%M:%S%z"))

    root = logging.getLogger()
    root.setLevel(level)
    root.handlers.clear()
    root.addHandler(handler)

def main() -> int:
    configure_logging(logging.INFO)

    request_id = uuid.uuid4().hex
    req = ChargeRequest(
        request_id=request_id,
        user_id="user_12345",
        payment_method_id="pm_abc123",  # safe token/id
        amount_usd=19.99,
    )

    try:
        txn_id = charge(req)
        logging.getLogger("app").info(
            "payment.completed",
            extra={"event": "payment.completed", "request_id": request_id, "txn_id": txn_id},
        )
        return 0

    except Exception:
        # Log exceptions once, at the boundary where you decide outcome.
        logging.getLogger("app").exception(
            "payment.failed",
            extra={"event": "payment.failed", "request_id": request_id},
        )
        return 1

if __name__ == "__main__":
    raise SystemExit(main())
```
