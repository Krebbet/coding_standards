# Version Control (Git & GitHub)

# Overview

1. SFL Scientific standards are to use git and GitHub for all project source code. 
    - For an introduction to Git and GitHub, please review these [internal slides](https://amedeloitte.sharepoint.com/:p:/r/sites/DOL-c-US-sflscientific/_layouts/15/Doc.aspx?sourcedoc=%7B5A9292AA-E10A-423E-A5EE-6C3BB0DD415E%7D&file=Git%2BGithub.pptx&action=edit&mobileredirect=true&DefaultItemOpen=1)
    - For Tools and Tips, see these [internal slides](https://amedeloitte.sharepoint.com/:p:/r/sites/DOL-c-US-sflscientific/_layouts/15/Doc.aspx?sourcedoc=%7BACFF6427-6891-4247-8366-C36895E63CF0%7D&file=Git%20Tools%20and%20Tips.pptx&action=edit&mobileredirect=true&DefaultItemOpen=1)
    - See below for specific commit, branching, and other standards
2. Repos should be updated throughout the project following the standards defined below. 
    - Developers will push code to development branches. Commits will be pushed from local environments to the remote Github repo every few days.
    - Development code will be merged to the master branch via pull requests upon completion of each feature.
    - Each pull request should follow the SFL Scientific coding standards.
3. All pull requests are to be reviewed by 1 QA team member and 1 technical peer. 
4. Both interim and final project code packages should be reviewed, signed, and tagged before being delivered to a client. 
5. All repos should be set up according to the SFL standards. Typically a PM will do this, but if you need to set up a Github repo yourself, please make sure you follow these instructions: ‣
